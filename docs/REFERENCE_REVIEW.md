# 참고 구현 검토와 적용 범위

검토일: 2026-09-15. 대상: [nashsu/llm_wiki README](https://github.com/nashsu/llm_wiki/blob/e8082119649e6a8e1cf85eaf289adcabfdf39d4e/README.md).
기능 설명을 검토한 기록이며 학술적 성능 근거나 본 프로젝트의 품질 보증이 아니다.

| 참고한 관점 | 이 프로젝트의 결정 |
| --- | --- |
| 사람이 탐색할 위키 목록과 명시적 페이지 연결 | 페이지·출처·역방향 참조 목록을 Java로 독립 구현 |
| 분석 후 페이지 생성의 두 단계 호출 | 확장 검토 사항으로 남김. 현재 컴파일은 한 번 호출 |
| 목적 문서로 범위 제한 | 현재는 컴파일 프롬프트와 가상 입력 문서로 범위를 명시 |
| 변경 없는 원문의 재처리 생략 | 보류. 원문 해시 외에 모델·프롬프트·출력 계약 변경도 캐시 키에 포함해야 함 |
| 작업 큐와 자동 갱신 | 보류. 단일 사용자 CLI와 명시적 발행 유지 |

추가한 기능은 [탐색 목록](navigation.md)에 설명한다. 참고 프로젝트의 코드·프롬프트·이미지는 복사하지 않았다.
참고 프로젝트의 [라이선스](https://github.com/nashsu/llm_wiki/blob/e8082119649e6a8e1cf85eaf289adcabfdf39d4e/LICENSE)는 GPL-3.0이며,
이 프로젝트의 자체 Java 구현은 Apache-2.0으로 배포한다.

## 단계별 컴파일을 확장한다면

첫 호출의 출력은 숨겨진 사고 과정이 아니라 주제 목록·사용할 출처 ID·페이지 연결 계획처럼 검토 가능한 구조화된 작업 결과로 정의한다.
다음 호출에는 이 계획과 원문을 함께 전달해 페이지를 생성한다.
계획과 최종 페이지의 출처에 대한 입력·출력 계약을 관리하고, 두 번째 호출이 실패하면 발행하지 않는다.

이는 컴파일 구현 선택지이며 Wiki RAG의 필수 조건은 아니다.
두 번 호출하면 비용과 실패 지점이 늘어난다. 현재 코드가 두 단계 컴파일 또는 품질 개선을 검증했다고 주장하지 않는다.
